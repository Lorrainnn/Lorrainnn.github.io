CS280A Project 1: Images of the Russian Empire

Baseline experiment showcase focusing on Part 1 Single-Scale Alignment and Part 2 Multi-Scale Pyramid.

Part 1: Single-Scale Alignment

Method / Implementation Overview: Basically, the method described as each glass-plate image is split vertically into Blue, Green, and Red channels. Blue is used as the reference. Green and Red are aligned independently by exhaustive search in a bounded displacement window using two pixel-based metrics (L2 distance and NCC). The best displacements are then applied to Green and Red before stacking channels back into RGB.

Summary: For these lower-resolution JPG inputs, L2 and NCC produce identical or very close displacements in practice. Single-scale exhaustive search is sufficient here, but becomes really expensive for high-resolution TIFF images since it matches from pixel to pixel, thus we introduce a multi-scale pyramid approach in P2.

Part 2: Multi-Scale Image Pyramid

Method / Implementation Overview: Direct exhaustive search on high-resolution TIFF images is costly, so alignment is performed coarse-to-fine with an image pyramid. We repeatedly downsample to a coarse level, solve for displacement there, then propagate upward by doubling the shift and refining in a local window at each finer level. The same pyramid pipeline is evaluated with both L2 and NCC under the same standard as P1.

Default setting for regular TIFF cases (except Emir and Melons special analyses about how different min_size would affect the results): min_size = 200.

Melons benefits from deeper coarse levels to bring large displacements into search range, while Emir can become less stable under aggressive downsampling due to cross-channel appearance mismatch in raw-pixel NCC. This sensitivity motivates more robust features since it's almost impossible to always manually adjust the parameter.

Bells & Whistles

A set of lightweight extensions that improve pipeline robustness and presentation. Each subsection below shows a concise before/after comparison using a representative image.

Better Features — Emir

Raw-Pixel NCC, min_size = 200

G shift: (24, 49)

R shift: (-455, 416)

Gradient NCC, min_size = 200

G shift: (24, 49)

R shift: (40, 107)

The baseline alignment compares raw pixel intensities using L2 or NCC. This works well for many images, but it can fail when the same physical object appears very different across the historical color filters. The case study image emir.tif is a good example: some regions, especially the clothing, have very different intensities in the blue and red channels.
To make the alignment less sensitive to absolute brightness, I computed the gradient magnitude of each channel and performed NCC alignment on the gradient images instead of the raw intensities. Gradients emphasize edges and spatial structure—such as facial contours, clothing boundaries, and architectural edges—while reducing the effect of large cross-channel brightness differences.
For Emir, raw-pixel NCC with a very coarse pyramid produced a clearly incorrect red-channel shift of (-455, 416). Using gradient features under the same pyramid setting produced a visually stable alignment with shifts G = (24, 49) and R = (40, 107). The gradient images are only used to estimate the displacement; the final RGB reconstruction still uses the original color channels.

Automatic Cropping — Wharf

Before

After

After alignment, the reconstructed images often contain unwanted border regions caused by the original glass plate, channel displacement, and circular shifting. A fixed crop percentage would be easy, but it would remove the same amount from every image regardless of its actual border size.
Instead, I detect likely border rows and columns near the image boundaries using simple image statistics. After converting the aligned RGB image to grayscale, I examine the mean intensity and standard deviation of rows and columns near each boundary. Rows or columns that are unusually dark or bright and have low intensity variation are treated as likely borders. I then crop the image to the remaining valid region.
I use wharf as the example because its boundary artifacts are easy to see before cropping. The automatic crop removes the distracting outer regions while preserving the main scene.

Automatic Contrast — Church

Before

After

Some reconstructed images occupy only a narrow portion of the available intensity range, which makes them look slightly flat or washed out.
I improve contrast using percentile-based intensity stretching. Instead of using the absolute minimum and maximum—which can be dominated by a few extreme pixels—I compute the 2nd and 98th intensity percentiles and map that range linearly to [0, 1]. Values outside the range are clipped.
This gives a simple form of automatic contrast enhancement without manually selecting brightness thresholds for each image. On church, the result produces clearer separation between dark and bright regions while keeping the overall appearance natural.

Automatic White Balance — Self Portrait

Before

After

Even after the channels are aligned, some reconstructions retain an overall color cast because the three historical exposures do not have identical average responses.
For white balance, I use the Gray World assumption: over a sufficiently varied scene, the average color should be approximately neutral gray. I compute the mean intensity of the R, G, and B channels, then scale each channel so that all three means approach a shared target value.
This is a simple global correction and does not require manually identifying a white object in the scene. On self_portrait, the adjustment reduces the overall color bias and produces a more balanced image. The result should be interpreted as a plausible correction rather than a ground-truth reconstruction of the historical colors.

Better Color Mapping — Melons

Before

After

The basic reconstruction assumes that the three historical photographic filters correspond directly to modern RGB display channels. In practice, those filter responses are not guaranteed to match modern RGB primaries exactly.
To explore a more flexible mapping, I apply a small linear 3*3 color transformation to the aligned RGB values. This allows each output color channel to depend slightly on all three historical channels rather than treating them as completely independent modern R, G, and B measurements.
I use melons as the example because its strong and varied colors make the effect of the mapping easy to observe. The transform improves color separation and produces a more visually expressive result. Since no calibration target or exact spectral response data is available, this transformation is an approximate color correction rather than a physically calibrated recovery.

Bells & Whistles Summary

Together, these five extensions improve both the geometric robustness and the visual quality of the reconstruction pipeline: gradient features make alignment more reliable, automatic cropping removes boundary artifacts, contrast stretching improves tonal range, white balance reduces global color casts, and color mapping provides a more flexible interpretation of the historical color channels.
